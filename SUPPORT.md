# Support

## Where to ask

Questions belong in the repository they are about, not here.

| Project | Where |
| --- | --- |
| Ragmux | [Ragmux/ragmux](https://github.com/Ragmux/ragmux/issues) · [ragmux.com](https://ragmux.com) |
| Contextator | [Contextator/Contextator](https://github.com/Contextator/Contextator/issues) · [contextator.com](https://contextator.com) |
| McpGuard | [Tunedness/McpGuard](https://github.com/Tunedness/McpGuard/issues) |
| AgentFuse | [Tunedness/AgentFuse](https://github.com/Tunedness/AgentFuse/issues) |

If a repository has Discussions enabled, a question goes there and a defect goes in
Issues. Where it does not, an issue is fine for both.

## Read first

Most questions are answered by the project's own README and its `docs/` directory:
configuration keys, environment variables, reverse proxy setup, database and volume
layout, and the limits of what the tool claims to do. Searching closed issues is worth
the thirty seconds it takes.

## Asking a good question

Include the version or commit, how you run it (Docker Compose, a binary, a clone), the
relevant part of your configuration with secrets removed, what you expected, what
happened, and the logs around the failure. Paste text rather than screenshots of text.

## What this is not

These are open source projects maintained by one person alongside other work. There is
no SLA on an issue, and no guarantee that a feature request will be built. Commercial
licensing and support arrangements exist for Ragmux and Contextator — ask through
[tunedness.com](https://tunedness.com).

## Security

Never in an issue. See [SECURITY.md](SECURITY.md).
